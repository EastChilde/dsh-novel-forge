> 目标读者：你（产品决策）+ 我（后续实现）。

## 0. 一页速览

| 项 | 内容 |
|---|---|
| **一句话** | 你说一个想法，它把想法变成一本**能连载、能续写、前后不矛盾**的小说，并且所有中间产物都是工作区里可读可改的文件。 |
| **产品形态** | DeepSeek Harness 插件：`/novel` 命令 + 对话内向导 +（P1）右侧「小说」工作台面板 |
| **核心差异** | 不靠「一次超长提示词写完」，而靠 **状态外置 + 分层拆解 + 质量闸门 + 确认点**。模型负责写，插件负责「记得住、收得回、不走味」。 |
| **默认假设** | **中文商业网文**（番茄/起点/七猫），文学向为可选模式；单章 2500 字；首本 20–30 万字（约 100 章 / 4 卷）；第三人称贴身限知 |
| **本版交付** | 从「一个想法」到「前 3 章正文 + 完整设定与大纲 + 可持续续写」的闭环 |

**它和「直接让模型写小说」的区别：**

1. 模型没有记忆，文件有。每一章开写前，插件从设定库、进度状态、伏笔账本里**装配**出这一章需要的那一小份上下文。
2. 模型不会收线，账本会。伏笔埋了哪一章、计划哪一章回收、逾期多少章，全部可查。
3. 模型容易跑飞，确认点会。默认在大节点停下来，让你看一眼再往下。

## 1. 调研：一部小说到底需要哪些「内容文件」

我把现有工具拆了一遍（Novelcrafter、Sudowrite、NovelAI、PlotPilot，以及两个成熟的 AI 长篇写作技能包），归纳出**八类**内容。这不是理论清单，是这些工具真正在维护、并且直接影响生成质量的东西。

### 1.1 八类必备内容

| # | 类别 | 具体内容 | 不做的后果 |
|---|---|---|---|
| 1 | **创意与定位** | 一句话故事（logline）、题材/赛道、读者预期、卖点、结局走向、参考对标 | 写着写着不知道在写什么，中期崩盘 |
| 2 | **设定圣经（Story Bible）** | 世界观与规则、势力、地点、人物档案、人物关系、道具/能力体系 | 设定漂移：第 3 章能飞，第 30 章忘了为什么不能飞 |
| 3 | **结构与大纲** | 全书结构（三幕/起承转合/节拍表）→ 卷纲 → 章纲（细纲）→ 场景/节拍卡 | 流水账、节奏塌陷、卷末没有高潮 |
| 4 | **正文** | 章节文件，一章一文件，带元信息 | 无法定位、无法局部重写、无法统计 |
| 5 | **运行状态** | 当前进度、人物位置/伤势/资源/已知信息、能力解锁、时间线、续写入口 | 新会话接不上；人物「瞬移」「失忆」 |
| 6 | **伏笔与承诺账本** | 埋设章、当前状态、计划回收章、逾期提醒、读者被许诺但没兑现的东西 | 烂尾、挖坑不填、读者流失 |
| 7 | **文风与语料** | 文风锚点（3 段样文）、正例反例、禁句表、AI 味词表、叙述视角规则 | 每章像不同人写的；越来越「AI 味」 |
| 8 | **质量与评审** | 可自动检查的硬指标、评审记录、修订历史 | 字数注水、对话占比失衡、章末没钩子 |

**两个加分项**（不进 M1）：参考书拆解（拆结构/拆爽点/拆人设）、平台数据反馈（追读率、完读率）。

### 1.2 现有工具的做法对照

| 工具 | 值得借鉴的点 |
|---|---|
| **Novelcrafter** | 把「设定」做成 **Codex**：条目有类型、别名、描述、关系、时间线演进（Progression）；正文里提到别名会自动关联；规划有 Matrix / Outline 两种视图；写作时按「场景节拍（scene beat）」逐拍生成 |
| **Sudowrite** | **Story Bible** 是强制的第一步：Braindump → Genre → Style → Synopsis → Characters → Worldbuilding → Outline → Beats，一层层收窄 |
| **NovelAI** | **Lorebook**：关键词触发的设定条目，按需注入上下文，而不是全量塞 |
| **PlotPilot（墨枢）** | 把长篇当**状态机**：章级摘要链、事件流、故事线 DAG、伏笔注册表、张力曲线、文风漂移检测、检查点回滚 |
| **novel-writer 技能** | 六阶段流程（需求→角色 DNA→大纲→情绪节拍→正文→分层润色）+ **可执行的检查脚本**（字数、AI 痕迹、代入感指标） |
| **oh-story 技能** | 卷纲/细纲/追踪三层文件；`追踪/_tracking-state.json` 是**唯一权威**，其余文件由它派生；「新增物三级」：直接写 / 补记 / 先问作者 |

### 1.3 三条结论（决定了本插件的设计）

1. **文件即真相。** 设定、状态、伏笔必须是结构化文件，不能只活在对话里。这样既能跨会话续写，也能让你随时手改、用 git 版本管理。
2. **必须分层拆解。** 全书 → 卷 → 章 → 场景 → 节拍。每一层解决不同问题：全书管走向，卷管升级，章管钩子，场景管「这一场戏好不好看」。
3. **AI 写长篇的真正瓶颈不是文笔，是三件事：记不住、收不回、走味。** 所以插件的重心是**追踪系统 + 质量闸门**，而不是更华丽的提示词。

## 2. 需求清单

### 2.1 P0 —— 没有它就不成立

| 编号 | 需求 | 说明 | 验收标准 |
|---|---|---|---|
| R1 | **立项** | 想法 → 3 个方向不同的故事提案 → 选定 → 硬约束确认表（题材/平台/篇幅/视角/基调/禁忌） | 输入一句话，2 分钟内拿到 3 个可选的提案卡 |
| R2 | **设定库** | 世界观、规则、势力、地点、人物卡（含欲望/恐惧/缺陷/秘密/弧光/说话习惯）、关系网 | 每个设定都是独立文件，可单独编辑；改完下一章立即生效 |
| R3 | **分层大纲** | 全书大纲 → 卷纲 → 前 N 章细纲（场景卡：目标/冲突/转折/信息差/情绪/钩子/字数） | 细纲能直接支撑写作，不需要再问「这章写什么」 |
| R4 | **单章写作** | 装配上下文 → 起草 → 自检 → 提交追踪 | 任意一章可独立重跑；重复写同一章结果稳定在设定范围内 |
| R5 | **状态追踪** | 进度、人物状态、时间线、能力、物品、伏笔账本、章节摘要、续写入口 | 新开一个会话说「继续写」，能准确接上停点 |
| R6 | **一致性校验** | 硬冲突（人名/能力/时间/物品/已死人物出场）+ 软提醒（伏笔逾期、人物失联、钩子重复） | 每章写完自动跑，冲突以「清单 + 三个处置选项」呈现 |
| R7 | **人工干预** | 重写本章、改某段、换视角、加长/砍半、润色、去 AI 味 | 任何一步都能退回前一版 |
| R8 | **导出** | Markdown 合集 / Word / EPUB / 平台纯文本 | 一条命令产出可直接投稿的文件 |
| R9 | **续写恢复** | 读三份关键文件 → 一句话复述停点 → 给下一步选项 | 冷启动恢复成功率高，且**不重新规划已确认内容** |

### 2.2 P1 —— 第二个版本

- **R10 批量连写**：日更模式，每轮 2–3 章，卷内连续生成，卷末停一次。
- **R11 质量报告**：张力曲线、爽点密度、对话占比、AI 味评分、钩子类型分布。
- **R12 拆书对标**：给一本参考书，拆出结构模板、爽点节奏、人设功能位，转成本书的规划建议。
- **R13 分支试写**：同一节点两个走向各写一章，你选一个，另一个存档。
- **R14 多书管理**：一个工作区多本书；系列共用设定库。
- **R15 侧边面板**：「小说」标签页 —— 项目树、进度、伏笔看板、章节卡、一键「写下一章」。

### 2.3 本版明确不做

插图/封面、多人在线协作、自动投稿、爬取平台数据、语音、翻译。

## 3. 项目文件规范

### 3.1 目录结构

一本书一个目录，全部是普通文件，随时可用 git 管理、用编辑器手改。

```text
NovelWriting/
└── books/
    └── 北境无神/
        ├── project.json              # 元信息：标题/题材/平台/篇幅/视角/进度/版本
        ├── 00-创意.md                # 想法原文 → 提案 → 最终确认的定位
        ├── 01-设定/
        │   ├── 世界观.md
        │   ├── 规则与力量体系.md
        │   ├── 势力.md
        │   ├── 地点.md
        │   ├── 人物-沈砚.md
        │   ├── 人物-老周.md
        │   ├── 关系网.md
        │   └── 文风锚点.md            # 3 段样文 + 禁句表 + 叙述规则
        ├── 02-大纲/
        │   ├── 全书大纲.md
        │   ├── 卷纲-01.md
        │   └── 细纲-001.md … 细纲-010.md
        ├── 03-正文/
        │   └── 第001章-雪夜借刀.md
        ├── 04-追踪/
        │   ├── state.json             # 唯一权威：人物状态/时间线/伏笔/续写入口
        │   ├── 进度.md                # 由 state 派生，给人看
        │   ├── 伏笔表.md
        │   ├── 时间线.md
        │   ├── 人物快照.md
        │   └── 章节摘要.md            # 滚动摘要链，供上下文装配用
        ├── 05-导出/
        └── .novel/                    # 索引与缓存，删掉可重建
```

### 3.2 章节文件与细纲（正文纯文本，元信息单独存）

正文只放正文，首行是章标题，不塞 front-matter——**同一份事实只存一处**，避免正文和元信息打架。

```markdown
# 第7章 借刀

沈砚推开门，风灌进来……
```

这一章的元信息放在 `02-大纲/细纲-007.md`，用固定模板（实现时已按此落地）：

```markdown
# 第007章 借刀

- 视角：沈砚
- 目标字数：2500
- 时间锚：第三日·黄昏
- 地点：城西旧宅
- 出场：沈砚、老周、褚九
- 情绪：紧张 → 痛快
- 章末钩子：悬念-老周在门外听见
- 伏笔埋设：铜钱背面刻字
- 伏笔回收：F004

## 场景 1
- 目标：拿到褚九的把柄
- 冲突：褚九反将一军
- 转折：把柄是假的
```

选 Markdown + `- 键：值` 而不是 YAML front-matter 的原因：人和模型都能直接读写，解析规则只有一条，出错能定位到行。

### 3.3 人物卡字段（关系一致性的根基）

```yaml
name: 沈砚
aliases: [砚哥, 沈七]
role: 主角
desire: 查清父亲死因            # 驱动他做什么
fear: 变成父亲那样的人          # 驱动他不敢做什么
flaw: 不信任何人                # 制造麻烦
secret: 他其实见过凶手
arc: 从「独自复仇」到「学会托付」
voice: 短句、少用形容词、习惯反问
body: 紧张时左手掐虎口；受伤后动作变慢
taboo: 不会主动解释自己         # 禁止行为，防止 OOC
```

### 3.4 状态文件（唯一权威）

`04-追踪/state.json` 是唯一权威，其他追踪文件都由它生成，**不要手改派生物**。

```json
{
  "last_chapter": 7,
  "time_anchor": "第三日 黄昏",
  "characters": {
    "沈砚": { "location": "城西旧宅", "condition": "左臂刀伤", "knows": ["褚九与县衙有往来"], "goal": "找内鬼" }
  },
  "abilities": { "听风": { "level": 2, "limits": "只能在安静环境用", "cost": "耳鸣半刻" } },
  "items": [{ "name": "半枚铜钱", "holder": "沈砚", "note": "父亲遗物" }],
  "foreshadow": [
    { "id": "F004", "text": "老周提到的「北边来的信」", "planted": 2, "status": "open", "due": 12 },
    { "id": "F012", "text": "铜钱背面刻字", "planted": 7, "status": "open", "due": 19 }
  ],
  "open_questions": ["谁在县衙里给褚九递消息？"],
  "next_entry": {
    "chapter": 8, "pov": "沈砚", "scene": "夜探县衙",
    "must": ["发现第二封信", "章末被老周撞见"],
    "forbid": ["揭晓内鬼身份", "让沈砚用出能力第三层"]
  }
}
```

### 3.5 三条硬规则

1. **正文可改，但要走「修订」，不静默覆盖**——每次覆盖前留旧版，冲突时给你 diff。
2. **状态只有一个权威文件**，其余是派生视图；派生文件可随时重建。
3. **所有文件都是纯文本**，不锁进数据库；换编辑器、换机器、进 git 都不丢。

## 4. 交互设计

### 4.1 三种节奏（同一个引擎，三种停靠密度）

| 模式 | 停几次 | 适合 | 流程 |
|---|---|---|---|
| **快车道** | 1 次（选题材方向） | 想先看看效果 | 想法 → 自动出设定+卷纲+前 3 章 → 一次总览 |
| **标准道**（默认） | 5 次 | 大多数情况 | 提案 → 设定 → 卷纲 → 前 10 章细纲 → 卷末回顾 |
| **精修道** | 每章 / 每场 | 已有明确想法，要逐句控 | 每章细纲确认 → 每章正文确认 → 可逐段改 |

模式可在设置里改，也可以一句话切换：「这次别问了，直接写三章」。

### 4.2 入口

| 入口 | 形态 | 说明 |
|---|---|---|
| 命令 | `/novel new`、`/novel write`、`/novel next` … | 熟手用，等价于自然语言 |
| 自然语言 | 「帮我写本小说，主角是个……」 | 自动识别意图，进入对应阶段 |
| 侧边面板（P1） | 标签页「小说」 | 看项目树、进度、伏笔、章节；点「写下一章」 |
| 设置页 | 「小说」分组 | 默认字数、模式、模型分档、禁句表、AI 味词表 |

### 4.3 主流程（标准道）

```text
 想法
  │
  ▼
[G1 提案] ── 3 个方向不同的故事提案 + 硬约束表
  │  通过 / 改 / 换方向 / 再来三个
  ▼
[G2 设定] ── 世界观·人物·关系·规则·文风锚点
  │  通过 / 改某个角色 / 只改世界观
  ▼
[G3 卷纲] ── 全书结构 + 第 1 卷卷纲（对手/冲突/代价/卷末爆点/钩子）
  │  通过 / 调结构 / 换结局走向
  ▼
[G4 细纲] ── 前 10 章场景卡
  │  通过 / 改某一章 / 加一章
  ▼
[写作] ── 逐章：装配 → 起草 → 自检 → 提交追踪
  │  每章汇报；每 3 章停一次；卷末 [G5]
  ▼
[G5 卷末] ── 指标汇总 + 伏笔变化 + 人物状态 + 下一卷入口
  │
  ▼
 导出
```

### 4.4 五个确认点上，你分别看到什么

| 关 | 产出 | 你会看到 | 可做的操作 |
|---|---|---|---|
| G1 | 3 个提案卡 | 一句话故事、主角（欲望/恐惧/缺陷）、核心冲突、3 条卖点、结局走向、风险提示 | 用第 N 个／改设定／换方向／再来三个 |
| G2 | 设定包摘要 | 每个主要角色 5 行、世界观 3 条硬规则、文风锚点 1 段 | 通过／改某人／加人／删线 |
| G3 | 全书骨架 + 第 1 卷 | 四幕走向、卷级升级曲线、卷末爆点、本卷代价 | 通过／调结构／换对手层级 |
| G4 | 10 张场景卡 | 每章一行：目标→冲突→转折→钩子→字数 | 通过／改某章／换顺序 |
| G5 | 卷末报告 | 字数、爽点密度、伏笔状态、人物状态、下一卷入口 | 继续／回头修／换卷走向 |

### 4.5 两种固定格式（交互契约）

**确认卡**——所有「要你拍板」的地方都用这个格式，保证你永远知道该回什么：

```text
【提案 2/3】《北境无神》
一句话：边陲小吏为查父仇，被迫替杀死父亲的人办事。
主角：沈砚｜欲望：查清真相｜恐惧：变成父亲那样的人｜缺陷：不信任何人
冲突：查案查到恩人头上，每查一步都要付一次人情债
卖点：① 反套路恩仇 ② 官场与江湖双线 ③ 主角每次赢都要先输
结局：真相是他父亲自愿赴死
风险：前 3 章信息密度偏高，需要刻意放慢

→ 回「用2」／「改：主角换成女性」／「再来三个」
```

**章节汇报**——每章写完固定这段，不超过 12 行：

```text
第 7 章《借刀》· 2,842 字
发生了什么：沈砚用假把柄诈出褚九的口风，反被点破，但意外发现内鬼是……
章末钩子：老周在门外听见了全部
新增：人物 1（褚九的打手）｜设定 1（县衙暗线）｜伏笔 F012（铜钱刻字，计划第 19 章回收）
自检：字数 ✓ 视角 ✓ 钩子 ✓ 连贯 ✓ ｜ 提醒：F004 已 12 章未推进
下一步：写第 8 章／先看第 8 章细纲／改这一章
```

### 4.6 命令表

| 命令 | 作用 |
|---|---|
| `/novel new` | 开一本新书（进入 G1） |
| `/novel idea` | 只讨论想法、出提案，不落盘 |
| `/novel bible` | 生成/增补设定 |
| `/novel outline` | 出全书大纲或某卷卷纲 |
| `/novel beat` | 出/改某几章细纲 |
| `/novel write 7` | 写第 7 章（缺前置会先补） |
| `/novel next` | 写下一章 |
| `/novel daily 3` | 日更连写 3 章 |
| `/novel revise 7` | 修订第 7 章（可指定：视角/节奏/对话/去 AI 味） |
| `/novel check` | 跑一致性 + 质量检查 |
| `/novel status` | 项目进度与伏笔状态 |
| `/novel resume` | 冷启动恢复 |
| `/novel export md\|docx\|epub` | 导出 |

### 4.7 停靠点与「防跑飞」

- **裸调用** `/novel`（不带明确意图）→ 只诊断项目状态，给 2–4 个白话选项，**绝不自动开写**。
- **批量上限**：单轮最多 3 章；日更默认 2 章；超出的提示「下一轮继续」。
- **切阶段即停**：从规划切到正文、从写作切到修订，都要一句确认。
- **不擅自扩大范围**：你说「写第 7 章」，它就只写第 7 章，不顺手把 8、9 也写了。

### 4.8 你想插手时的三种颗粒度

| 颗粒度 | 怎么做 | 影响 |
|---|---|---|
| **章** | 「重写这章」「换沈砚视角」「写短一半」 | 重跑单章，旧版存档 |
| **段** | 选中一段 →「这段太 AI 了」 | 只重写该段，保持前后衔接（P1 面板支持选区） |
| **设定** | 「沈砚不该会武功」 | 先做**影响面分析**：哪些章引用过 → 给你「改前文 / 加修订说明 / 当新信息」三选一 |

### 4.9 写作中冒出新东西怎么办

AI 写着写着会自己发明设定。按影响分三级，避免「偷偷加设定」：

| 级别 | 例子 | 处理 |
|---|---|---|
| **直接写** | 路人、地名细节、一次性对话 | 不打扰你 |
| **补记并报备** | 具名配角、新伏笔、复用地点的新属性 | 写进申报表，章末汇报里列出，你确认后进入权威状态 |
| **先问** | 主线反转、金手指新规则、真相揭晓、改变已定细纲 | 停笔，先问 |

### 4.10 失败兜底

| 情况 | 处理 |
|---|---|
| 字数不达标 | 补场景/补细节，**最多 +20%，不注水**；仍不够就报「这章撑不到 2500」并给两个选项 |
| 章末没钩子 | 不硬编，从钩子库（13 式）里挑一个和本章逻辑自洽的 |
| 设定冲突 | 停写 → 冲突清单 → 三选一 |
| 越写越 AI 味 | 用文风锚点重写该段，并记录触发的词表项 |
| 输出被截断 | 自动分段续写并拼接，标记断点 |

## 5. 质量闸门（每章自动跑）

硬指标用规则算，软指标用模型判，**结果分「阻断 / 提醒」两级**。

| 检查项 | 规则 | 级别 |
|---|---|---|
| 字数 | 目标 ±15% | 阻断 |
| 视角一致性 | 全章不出现 POV 人物不可能知道的信息（启发式 + 模型复核） | 阻断 |
| 章末钩子 | 最后 200 字含悬念/未完成动作/新信息 | 提醒 |
| 对话占比 | 20%–45% | 提醒 |
| 句式重复 | 连续 3 段同结构、相同句首 ≥3 次 | 提醒 |
| AI 味词表 | 「仿佛/不禁/顿时/一丝/不易察觉/意味深长…」密度阈值，可配置 | 提醒 |
| 人名一致性 | 与别名表比对，禁止新造称呼 | 阻断 |
| 时间线 | 章内时间锚单调，不与已发生事件冲突 | 阻断 |
| 人物失联 | 主要角色连续 N 章未出场 | 提醒 |
| 伏笔逾期 | 超过计划回收章仍未回收 | 提醒 |
| 爽点密度（网文模式） | 每 ~2000 字至少 1 个情绪峰值，相邻不得同类型 | 提醒 |

## 6. 技术方案（概要，供你判断可行性）

| 层 | 做法 |
|---|---|
| **插件形态** | DSH 插件（host 工具 + 可选 client 面板）。`dsh.bundle.patch` 挂载；host 侧 `inject: ['tools']` |
| **工具** | 约 10 个 `defineTool`：`novel_init`、`novel_plan`、`novel_bible`、`novel_outline`、`novel_write`、`novel_commit`、`novel_check`、`novel_status`、`novel_export`、`novel_resume` |
| **方法论** | 写作方法、网文规则、检查清单以 Markdown 参考文件随包分发，**按阶段按需注入**，不整包塞进上下文 |
| **模型路由** | 规划/结构用强模型，正文用文风稳的模型，检查用便宜模型；可在设置里分档 |
| **上下文装配** | M1 用「结构化检索」：本章出场人物 + 涉及地点 + 待回收伏笔 + 上章摘要 + 本章细纲 + 文风锚点。P2 再加向量检索 |
| **校验器** | 纯函数规则引擎（字数/句长/词表/别名/时间线/伏笔账本）+ 模型评审 |
| **存储** | 工作区内普通文件；`state.json` 单一权威；原子写 + 旧版备份；派生文件可重建 |
| **面板（P1）** | 若已装 `dsh-better-sidebar`，注册一个「小说」标签页；否则降级为对话内卡片 |
| **安全边界** | 只写工作区；覆盖已有手改文件前必须确认；不联网抓取 |

## 7. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| **AI 味** | 排比、总结句、每段都在解释 | 文风锚点 + 禁句表 + 词表检测 + 定向重写 |
| **前后矛盾** | 能力滥用、人物瞬移、死人复活 | 状态文件 + 校验器 + 三级新增物申报 |
| **注水凑字** | 字数够了但没内容 | 硬指标只做下限，另查「无功能段落」（不改变局势的对话/环境） |
| **烂尾** | 伏笔不收、卷末没爆点 | 伏笔账本带 due 章 + 逾期提醒 + 卷末检查 |
| **成本** | 长篇反复装配上下文 | 分层摘要 + 只注入相关条目 + 检查用小模型 |
| **失控** | 一键生成 30 章没人看 | 批量上限 + 确认点 + 随时可停 |
| **版权/抄袭** | 模仿参考书过近 | 只学结构与节奏，不搬具体桥段；参考书仅作拆解，不做续写 |

## 8. 里程碑

| 阶段 | 交付 | 判断标准 |
|---|---|---|
| **M1 闭环** | 立项 → 设定 → 卷纲 → 10 章细纲 → 3 章正文 → 追踪 → 导出 | 给一个想法，能拿到 3 章像样正文，且新会话能续写 |
| **M2 长篇** | 卷纲批量、日更、校验器、恢复、导出 docx/epub | 连续写 30 章不走味、伏笔不丢 |
| **M3 工作台** | 侧边面板、质量报告、拆书对标、分支试写 | 不用记忆命令也能操作 |

## 9. 已确认的决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 主攻场景 | **中文商业网文**（番茄/起点/七猫）；文学向作为可选模式，两套结构规则不混用 |
| 2 | 交互重心 | **对话为主**；侧边面板放 M3 |
| 3 | 自动化程度 | **只在大节点停**（G1/G3/G5 + 首次前 10 章细纲）；章内连续写，每 3 章汇报一次 |
| 4 | 默认篇幅 | 单章 **2500 字**，首本 **20–30 万字**（约 100 章 / 4 卷）；立项时可改 |
| 5 | 交付格式 | **Markdown**；docx/epub 放 M2 |
| 6 | 拆书对标 | **要**，放 P1 |

沿用默认的两项：插件名 **墨匣（novel-forge）**；首发**只做中文**。
